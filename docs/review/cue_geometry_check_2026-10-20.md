## 3. 第二个缺陷：cue 速度恒为 0

`[cue-track]` 15 条记录里，速度字段**全部是 `(0.000,0.000,0.000) m/s`**：

```
idx=600  id=101 submitted=1 phase=1 中心ECEF=(-6200831.0,714755.5,5273706.0) 速度=(0.000,0.000,0.000)m/s
idx=2400 id=101 submitted=1 phase=1 中心ECEF=(532848.3,348611.0,8471024.0)   速度=(0.000,0.000,0.000)m/s
```

宿主侧 `lrdr_sensor_1q.cpp:1466-1476` 的算法是"相邻两次融合位置差分 / dt"；实际 dt 为 0 或
fix 未刷新时差分为 0 ⇒ 速度恒 0。后果：库内在 `kCoasting` 阶段按 `位置 + 速度×dt` 外推，
速度 0 等于**死守最后一帧位置**，而目标以约 6 km/s 飞行 ⇒ 每错过一拍就滞后约 6 km。

## 4. 融合帧统计（`[cue]` 行）

```
[cue] idx=600  fixes=5 matched=1 rejected=4 designate=101
[cue] idx=830  fixes=4 matched=0 rejected=4 designate=0
[cue] idx=10000 fixes=5 matched=0 rejected=4 designate=0
```

- 每周期有 **3–5 个候选定位帧**；
- 只 `matched=1`，其余 **3–4 个被 rejected**；
- 被采纳的那一帧在多个周期上与真值差上千公里 ⇒ **选帧/定轨逻辑可疑**（可能与几何精度因子、
  双星构型、或关联门限有关）。

## 6. 处置建议（按优先级）

| # | 归属 | 措施 |
|---|---|---|
| 1 | **融合侧** | 选帧时加入"与雷达自身航迹/上次 cue 的位置一致性门"，剔除跳变 > 100 km 的帧；只用几何精度最高的帧 |
| 2 | **适配层** | fix 未刷新时用**上次有效速度**外推，不允许速度恒 0（`lrdr_sensor_1q.cpp:1466`） |
| 3 | **雷达侧（本次可做）** | 外部 cue 合理性门：与上一 cycle 的 cue 位置跳变 > 阈值（如 500 km/拍）或与已有航迹偏差过大时，本周期**只照中心 1 拍**，省下的槽位回退搜索 / 库内跟踪 —— 与 T-04b 配额化合并实施 |
| 4 | **雷达侧（必做）** | T-04b：搜索保底配额 + 外部窗跨周期续扫，避免单一信源吃满预算 |

**实施状态（2026-10-20）**：第 3、4 条已实施（1q `8dcdfb98` / BJ `033f04e`）。

| 措施 | 实现 | 参数 |
|---|---|---|
| 搜索保底配额 | `RirSession.cpp` 槽位预算：先留搜索再分配 | `kMinSearchDwells = 4` |
| 库内航迹保底 | 同上 | `kMinInternalTrackDwells = 2` |
| 外部窗跨周期续扫 | 窗口序列按「中心优先」构建 + 游标推进（新 cue 归零） | `kExternalWindowMaxPoints = 128`（取全序列） |
| cue 合理性门 | 位置跳变 > 最大速度 × 间隔 + 容差 ⇒ 只照中心 1 拍 | `kCueGateMaxSpeedMps = 10000`、`kCueGateSlackM = 50000` |

预算效果（20 槽/周期）：指定 0–1、外部 13–14、库内 ≤2、搜索 ≥4。cue 降级周期外部只 1 拍，
其余槽位回退搜索。

**结论**：外部驻留与自主搜索不仅"区域"差 293 倍，目前更严重的是一半以上的时间**连目标都没照到**；
根因在 cue 源（位置间歇性错误 + 速度恒 0），雷达侧的换算是正确的。
