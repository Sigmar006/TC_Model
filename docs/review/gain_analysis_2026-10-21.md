## 二、MTI 增益为什么为负

### 1. 公式

```cpp
double MtiPowerResponse(double fd, double prf) {
  const double folded = FoldIntoPrf(fd, prf);          // 折进 ±PRF/2
  const double sine = std::sin(kPi * folded / prf);
  return 4.0 * sine * sine;                            // 2 脉冲对消器
}
```

- `f_d → 0`（或 PRF 整数倍）时为 **0**（−∞ dB）：这就是经典的 MTI **盲速**；
- `f_d = PRF/2` 时为 4（**+6 dB**）：对消器相干积累上限。
- 因此 MTI 增益的取值范围天生就是 `(−∞, +6] dB`，**负值本身是正常输出**。

### 2. 本例为什么落在 −52 dB

第 1774 周期日志里的双程多普勒是 **+48,290.004 Hz**（与真值径向速度 +2,414 m/s 一致，
`f_d = 2·f_c·v_r/c = 20·v_r`）。

而 **PRF = 10 Hz**：

```
折叠：48,290.004 mod 10 = 0.004 Hz   →  MTI = 4·sin²(π·0.004/10) = 6.3e-6  →  −52.0 dB
```

第 1126 周期同理：`35,460.005 mod 10 = 0.005 Hz` → −50.1 dB（日志 −49.88，吻合）。

**关键点**：PRF=10 Hz 对应的无模糊速度只有

```
v_max = λ·PRF/4 = 0.1 × 10 / 4 = 0.25 m/s
```

而目标径向速度约 **2,400 m/s**，是其 **~10,000 倍**。多普勒早已完全混叠，
折叠后的相位只等于"大数的小数部分"——速度变化 0.05 m/s 就能让折叠值跨 1 Hz，
把 MTI 从 −∞ dB 扫到 +6 dB。

⇒ **负值不是算错，而是这个 PRF 下 MTI 对高速目标根本没有物理意义。**
实测 MTI < −10 dB 的周期占 **10.2%**（130/1,277），中位 +3.1 dB，正是"均匀扫过响应曲线"的表现。

## 三、MTD 增益为什么恒 ≤ 0

```cpp
double DftBinPower(...) {   // 归一化到峰值=1
  const double magnitude = numerator / (kMtiMtdChannelCount * denominator);
  return magnitude * magnitude;                       // ≤ 1
}
candidate.mtd_gain_db = ToDecibels(DftBinPower(fd, selected_channel, prf));
```

归一化到理想匹配 bin 的峰值 1（0 dB），所以它是**跨 bin 损耗**而不是增益：
多普勒落两个 bin 之间时最多损失约 3.9 dB，正好覆盖实测的 −3.86 … 0 dB。
⇒ **这个字段叫"增益"是误导，实际是损耗**，数值正确。

---

## 四、"总增益为负"的性质：口径矛盾，不是数值错误

`总增益 = 脉压 + MTI + MTD`，把**旁路** MTI（−52 dB）加进了一个看起来像"处理链总增益"的字段。
但该旁路**不进 SINR**——`MtiMtdAcceptanceBank.cpp` 文件头明确写着"验收旁路 2 脉冲 MTI + 8 路 DFT MTD
（频谱效能，**不进 SINR**）"，且全仓库只有 `RirAcceptanceRecords.cpp` 引用它，检测链从未使用。

所以同一周期出现：

- `总增益 = −3.37 dB`（旁路口径：目标被对消）
- `SNR = 18.47 dB，检测=是`（检测链口径：目标清晰可见）

两条都"对"，但它们**不是同一条通路**，日志没有任何标注说明这一点。

## 五、结论

| 问题 | 判定 |
|---|---|
| MTI 增益为负 | **数值正确、物理在 PRF=10 Hz 下无意义**（多普勒混叠 1 万倍） |
| MTD 增益为负 | **定义如此**（归一化 DFT 的跨 bin 损耗），名字误导 |
| 总增益为负 | **口径混淆**：把不进 SINR 的旁路指标加进了"总增益" |
| 与"检测=是"并列 | 不是矛盾，是两条通路；但日志未标注 |
