## 3. 代码级根因

### 3.1 发射点：**它不是地面点，是"100 km 高度回推点"**

`TargetInferenceEngine.cpp:248-289` 的 `backtrack` 有三个停机门，只有"地表交点"才把高度归零：

```cpp
if (r_next <= earth_radius)        { … *hit_surface = true;  }   // 地表 → 高度归零
if (r_next - earth_radius <= 100 km) { return next; }            // 大气界面 → 保留空中高度
if (|v| <= launch_speed_threshold)   { return next; }            // 速度门 → 保留空中高度
```

`launch_atmosphere_interface_altitude_m = 100,000`（配置默认值）。
⇒ 报出的"发射点"是弹道在 **100 km 高度** 处的回推点，位于真实发射场**下风向约 200 km**，
这与实测 219 km 完全吻合；高度 106.9 km 中的 6.9 km 则是
**球面判据（赤道半径 6,378,137 m）与 WGS84 椭球高混用**产生的伪高差
（代码注释里已承认"中纬度约 +5 km 伪高差"）。

### 3.2 对非弹道目标也输出"发射点/落点"

指挥所-1 是静止地面目标（v≈0），回推一步即触发速度门（30 m/s），
返回的是 51.8 km 高度的空点——**这类目标本不该有发射点/落点**。
代码没有 `|v|` 下限或高度下限的合理性校验。

### 3.3 落点 9,141 km 偏差：**不是传播器的错，是输入状态**

用第 20 项同一拍的"当前位置 + 航路点"反推运动方向：

| 量 | 值 |
|---|---|
| 当前（键 104） | (43.508, 109.389, 334,418 m) |
| 10 s 后航路点 | (43.616, 109.149, 326,117 m) |
| 推出速度 | 北 +1.2 km/s、西 −1.9 km/s，下降 0.83 km/s |
| 沿该方向推至地面 | ≈ (45.7, 104.2) ✓ **与预测落点一致** |

⇒ 传播器**自洽**。偏差只能来自**输入的状态（位置/速度）与实际弹道不符**。
而验收行没有记录输入的 r/v，**当前日志无法判定**是"轨道是鬼影/漂移"还是"键映射错"。

## 4. 建议修复（按优先级）

| # | 问题 | 措施 |
|---|---|---|
| **1** | 发射点语义错误 | 二选一：**(a)** 继续穿过大气回推到地表（无推力模型下会偏，但至少是地面点，需给大 1σ）；**(b)** 保留 100 km 停机点但**改名为"助推段上界点"**，另按 `v·t` 粗略投影到地面作为"发射点估计" |
| **2** | 非弹道目标也输出 | 加合理性门：`|v| < v_min`（如 500 m/s）或 `高度 < 100 km` 时输出`不适用(非弹道目标)`，不发落点/发射点 |
| **3** | 无法追溯输入 | 验收行或诊断补 `输入位置/速度`（至少速度），否则 9,141 km 的偏差无法归因 |
| **4** | 球面/椭球混用 | 地面判据改用与 LLA 一致的半径（按点计算的地心半径），消除 ~7 km 伪高差 |

## 5. 需要确认

1. **目标键 ↔ 场景目标 ID 的映射**：融合 DP 的 key 是自编号还是沿用场景 ID？
   若是自编号，验收日志应同时打印场景目标 ID，否则"预测偏 9,141 km"无法定位到具体目标。
2. **发射点是否必须为地面点**：若验收判据要求"发射点地理位置"，则必须选措施 1(a)/(b) 之一，
   当前实现（空中点）不能作为发射点通过。
