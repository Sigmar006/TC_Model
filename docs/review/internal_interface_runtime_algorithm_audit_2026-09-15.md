# 红外与雷达内部接口运行及算法真实性审查

审查日期：2026-09-15

## 1. 结论

70～77 项内部接口均存在日志输出，现有场景日志未发现 NaN、Inf、负协方差或明显越界值。
雷达方程、CFAR、全局关联、Kalman/IMM、红外辐射噪声、角误差和跟踪滤波均有实际计算，
不能笼统认定为固定返回值或空壳算法。

但当前证据 **不能判定内部接口全部满足验收要求**，主要原因如下：

1. 第 70、71、75 项所谓“上游输出/下游输入”由同一个变量连续打印，属于同源值自证，
   不能独立证明接口传递正确。
2. 当前 RIR 场景启用 `kSnrFallback`：统计检测标志为“否”的 24 个周期仍形成量测，且量测
   位置直接取场景目标真值。本次运行未覆盖雷达误差采样量测路径。
3. SBIRS 的 `kEstimated` EKF 初始化直接装入目标真值位置和真值速度，后续滤波计算虽真实，
   但当前场景不能证明滤波器只依靠传感器量测自主初始化、收敛。
4. 当前验收场景把红外 WFOV/NFOV SNR 门限设为 `0.001`，而实际 SNR 均约为 70，未覆盖
   辐射 SNR 不足的拒绝路径。

因此，当前总体判定为：**接口可输出、数值基本合理、核心数学模块并非空壳，但验收场景存在
真值辅助和门控旁路，接口对账日志也缺少独立性，尚不能据此证明完全按合同要求执行。**

## 2. 主要问题

### 高：RIR 回退模式绕过统计检测结果，并直接使用真值量测位置

- `RirController.cpp:694-696` 在 `kSnrFallback` 下用 `SNR >= 6 dB` 决定是否准入，而不是使用
  `detection.detected`。
- `RirController.cpp:783` 先将 `built.position` 设为场景目标位置；`797-799` 在回退模式直接提交，
  只有非回退模式才在 `800-823` 施加偏差并抽样量测误差。
- 当前场景 `rir_ground_site_recognition.json:308` 配置为 `kSnrFallback`。
- 日志中第 71 项共 332 条，其中 24 条为“检测标志=否”；第 72 项仍有 332 条量测，即这 24 条
  仍进入关联/滤波。该行为与验收文档 `functional_acceptance_test_criteria_ocr.md:1201-1202`
  “检测失败不得生成有效量测”不一致。
- 已有量测专项统计表明，记录位置与场景真值距离的最大差约 0.05 m，仅为日志小数位舍入量级。

影响：关联和滤波实现本身是真实算法，但当前日志没有验证真实检测门和误差量测输入，不能作为
“检测判决 → 量测 → 跟踪”完整链路通过的充分证据。

### 高：SBIRS 估计跟踪初始化存在真值注入

`SbirsTrackingCoordinator.cpp:53-59` 使用 `target.position_eci_m` 和
`target.velocity_eci_m_per_s` 初始化 EKF/IMM 的 6 维状态；调用点位于
`SbirsPipeline.cpp:1990-2002` 的 `kEstimated` 路径。角度 CV-KF 分支使用测角初始化，但当前默认
后端为 `kEkf`（`SbirsPolicyConfig.h:99`），场景没有覆盖该配置。

后续预测、动态量测协方差、Joseph 形式更新及 NIS 计算是真实执行的，但初始状态已接近真值，
因此当前第 77 项不能证明纯传感器量测条件下的起始距离估计和收敛性能。

### 高：第 70、71、75 项接口对账是同一变量重复输出

- 第 70 项在 `RirAcceptanceRecords.cpp:366-373` 将同一 `input.cell` 字段分别标记为“计算输出”
  和“处理入口”。
- 第 71 项在 `RirAcceptanceRecords.cpp:382-390` 将同一 `detector_snr_db` 分别标记为“处理输出”
  和“检测器输入”。
- 第 75 项在 `SbirsPipeline.cpp:1427-1428`、`2176-2179` 将同一 `snr/context.snr` 分别打印为
  模块输出和模块输入。

日志中这些字段当然 100% 相等，但相等由日志拼接方式保证，不能发现结构体映射、单位换算、缓存
错位或下游实际消费其他值的问题。应在生产结果落入明确 DTO 后，于真实消费者入口分别采样，或由
契约测试构造不同哨兵值验证字段映射。

### 中：雷达特征提取主要消费场景签名表，不是原始回波反演结果

`RecognitionObservationBuilder.cpp:52-67` 直接把场景目标的 `aspect_rcs_samples`、
`polarization_samples` 和 `range_rcs_scatterers` 交给三个特征提取器；运动特征来自滤波航迹。
各提取器确实执行视角选择、SNR 门控、距离补偿、峰值统计和质量计算，识别器也执行动态加权及
高斯相似度匹配（`RecognitionMatcher.cpp:120-205`），并非固定类别返回。

但这属于“基于外部目标特征表的效能级识别”，不能等同于从本次回波 IQ/距离像数据完成特征反演。
若合同要求后者，第 73 项当前实现和日志不足；若合同允许目标电磁特性作为仿真输入，则该实现可接受，
但需在合同符合性矩阵中明确建模层级。

### 中：红外检测场景未覆盖低 SNR；复合门标注已修复

场景 `sbirs_triple_sat_fix_messages.json:41-46`、`77-82`、`113-118` 将门限设为 `0.001`，
远低于公共配置默认的 WFOV `4.0`、NFOV `6.0`（`SbirsPolicyConfig.h:19-20`）。320 条第 75 项
SNR 范围为 70.017325～70.344501，全部通过纯 SNR 门限。

修复前日志有 83 条“检测标志=否”，WFOV 标志实际为 `in_wfov && snr >= threshold`
（`SbirsPipeline.cpp:1391-1432`），NFOV 标志为复合的 `tracking_gate_passed`
（`SbirsPipeline.cpp:2180-2182`）。数值并不矛盾，但字段名称和验收文档“必须与门限结果一致”容易
误判。应分别输出 `SNR门结果`、`几何门结果` 和 `综合准入结果`。

解决状态：第 75 项现分别输出 `SNR门结果`、`视场门结果` 和 `综合准入结果`，NFOV 另输出
`稳定帧门结果`；门限覆盖不足仍需通过新增低 SNR 场景解决。

### 中（已修复）：文档中的内部接口日志路径与代码不一致

验收文档 `functional_acceptance_test_criteria_ocr.md:1165-1166`、`1290-1292` 声明 70～73 写入
`log/rir_acceptance.log`、74～77 写入 `log/opir_acceptance.log`；实际通道默认路径为
`AcceptanceFileLog.cpp:40-44` 中的 `log/IRInternalInterface.log` 和

解决状态：验收文档现已将 70～73、74～77 分别指向实际内部接口日志，并在附录中拆成独立条目。

### 低（已修复）：红外有效噪声日志单位标注错误

噪声模型已统一为“积分时间内噪声能量”口径，`SbirsNoiseModel.h:25-32` 说明字段名 `_w` 只是沿用；
光子、热、读出噪声在日志中也标为 J，但修复前两处第 75 项日志将有效噪声标为 W。
计算仍按 `signal_energy / effective_noise` 执行（`SbirsPipeline.cpp:565-586`），数值自洽，问题在于
验收日志单位，建议改为 J 或明确写作“等效噪声能量”。

解决状态：第 75 项 WFOV/NFOV 日志均改为 `有效噪声能量=<值>J`，辐射模型声明同步明确 J 口径；
计算公式和数值不变。

## 5. 运行与合同边界

- 已有运行日志：`log/RadarInternalInterface.log`、`log/IRInternalInterface.audit.log`。
- 重新构建当前示例时，核心库生成成功，但 `examples_core` 因验收构建缓存使用 C++14 而代码使用
  `std::filesystem`，且示例目标缺少 `src` 私有头文件搜索路径而失败；因此本报告的动态统计来自现有
  二进制生成的日志，静态调用链按当前源代码复核。当前构建目录没有注册 CTest 测试。
- `functional_acceptance_test_criteria_ocr.md:1155-1159` 明确说明原始测试材料没有提供独立的内部接口
  测试名称和判定阈值。未提供签署合同中的算法公式、参数表及允许的真值辅助边界时，只能判断当前
  实现是否真实计算、是否与仓库验收文档一致，不能最终签署“完全符合合同算法”。

## 6. 建议的验收补测顺序

1. RIR 改用 `kDetectorGate` 重跑，要求第 71 项“否”与第 72 项无量测逐周期严格对应，并验证量测
   误差统计符合协方差。
2. SBIRS 增加无真值状态初始化用例，或明确合同允许的初始距离/速度来源，再验证 EKF/IMM 收敛。
3. 将 70、71、75 的生产者和消费者采样点拆开，增加 DTO 字段哨兵映射测试。
4. 红外使用默认或合同门限，构造门限上下两侧样本，分别验证 SNR 门、几何门和综合准入门。
5. 明确第 73 项是“效能级签名表识别”还是“回波级特征反演”；按合同层级补对应数据链和测试。
