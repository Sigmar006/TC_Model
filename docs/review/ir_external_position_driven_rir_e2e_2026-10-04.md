# 外部位置驱动 RIR 的端到端实测（2026-10-04）

Status: draft
Authority: 开发期度量记录（非契约、非模块设计）
Answers: 双星交会的位置/速度作为外部输入时，雷达能否完成指向、探测、跟踪、识别

> 本文把前几轮的纸面对账变成实测，并**修正了前一轮判定中的一处乐观结论**：
> 指向精度确实充足，但"搜索模式下能否照到目标"由**波位表重访时间**决定，
> 不由位置精度决定。

## 1. 被测链路与设置

链路（与外部位置录入接口的目标形态一致）：

```
外部位置（含横向误差 delta）-> 反算指向 -> 运行期补丁设 scan_center
  -> RIR 逐周期探测 -> 建航确认 -> 识别积累 -> 识别结论
```

| 项 | 值 |
|---|---|
| 工具 | `tools/measure_rir_from_fix/`（独立 CMake，链接已安装的 1q 库） |
| 场景 | 雷达在原点；目标正东 200 km、高度 200 km（仰角 45°）；RCS 10 m²；Swerling0；速度 300 m/s 沿 +y |
| 误差注入 | 横向偏移 delta（双星交会误差的主导分量），指向误差 = atan(delta/斜距) |
| 判定量 | `RirOutputDebugView`（帧作用域快照，不改变执行语义） |
| 可扫描体积 | 放开到全空域（默认 az ±60/el ±30 装不下 45° 仰角，会被体积门排除） |

**为什么这样注入**：目标真值始终在真实位置，带误差的位置**只用于指向**——这精确重演了真实链路"用有误差的位置去指、看能不能照到真目标"。

## 2. 结论一：**指向精度充足**（修正前一轮的乐观点）

`designate` 模式（每周期第一个驻留对准目标，等价于"外部位置直接驱动指向"）：

| delta (m) | 指向误差 | 检出周期 | 建航周期 | 最大命中 | 识别周期 | 观测数 |
|---:|---:|---:|---:|---:|---:|---:|
| 0 | 0.000° | 25/25 | 25/25 | 25 | 23 | 23 |
| 375 | 0.107° | 25/25 | 25/25 | 25 | 23 | 23 |
| 5,000 | 1.432° | 25/25 | 25/25 | 25 | 23 | 23 |
| 10,000 | 2.862° | 25/25 | 25/25 | 25 | 23 | 23 |
| **30,000** | **8.531°** | **25/25** | **25/25** | **25** | **23** | **23** |

**关键读数**：即使横向误差 30 km（指向误差 8.5°，远超 2° 主瓣门），只要**指向由外部位置直接驱动**，仍 100% 检出、100% 建航。

**原因**：指定/外部驻留的指向取自该位置方向，目标落点与指向同源，"指向误差"在该模式下不构成失配。所以**位置精度不是这一段的瓶颈**。

## 3. 结论二：**搜索模式的瓶颈是波位表重访时间**（新发现）

`search` 模式（仅设 `scan_center`，等价"设定方位俯仰进行扫描"）：

| delta (m) | 检出周期 | 排除周期 | 逐周期模式 |
|---:|---:|---:|---|
| 0 ~ 30,000（全档） | **0/25** | **25/25** | `XXXXXXXXXXXXXXXXXXXXXXXXX` |

**零偏移、完美指向也一次都照不到。** 根因定量如下（`scan_center` 设为全空域体积后）：

```
方位 360°/4° + 1 = 91 档
俯仰 180°/4° + 1 = 46 档
波位表 = 91 x 46 = 4186 点
每周期驻留槽位 = floor(dt / recognition_dwell_sec) = floor(0.5 / 0.05) = 10
全扫一遍 = 4186 / 10 = 419 个周期 = 209 秒
目标仰角 45° 位于俯仰第 34 档 => 游标需推进约 3071 步 => 约 307 个周期
```

实测驻留中心逐周期确认：首周期 `(180.000, 90.000)`（波位表首点，位于西北上），25 周期内始终停在**俯仰 90° 附近**——游标远未推进到目标所在行。

**⇒ 当 `scan_center` 指向半个天空、而目标只占 0.4° 立体角时，4° 波束需要 209 秒才扫一遍，25 拍内不可能照到目标。** 这不是位置精度问题，是**搜索立体角与重访时间的匹配问题**。

## 4. 结论三：识别未达门限（属测试场景不足，非能力结论）

`designate` 模式下识别链贯通（23/25 周期有识别结论、观测数 23），但**最高置信度 0.240 < 门限 0.70**。

本测试场景只给了目标的 `rcs`，**没有给 `aspect_rcs_samples` / `polarization_samples` / `range_rcs_scatterers` 三项识别特征真值**，特征匹配分自然偏低。

**⇒ 该数值不构成"识别能力不足"的结论**，只说明本简化场景不足以跑到识别确认。要测识别上限，需按 `sbirs_triple_sat_fix_messages` 那样铺特征真值。

## 5. 对方案的含义（三条）

1、**"外部给位置 -> 指向目标 -> 探测跟踪"链路成立**，且对位置精度不敏感（30 km 误差仍通）。
2、**但 `scan_center` 不是合适的指向手段**：它是扫描基准，配合大体积会把重访时间拉到百秒量级。真正需要的是"**在该方向上驻留照射**"（即指定/外部驻留那一类），这也是前几轮 Stage A 里判定 `has_scan_center` 不满足需求的实测佐证。
3、**交付给雷达的不只是位置，还必须包含"这是外部指定的照射方向"这一语义**——否则雷达会把它当搜索基准，落入 209 秒重访的陷阱。

## 6. 未覆盖 / 待补

- **识别上限未测**：需在场景中铺齐三类识别特征真值后重测。
- **速度外推在闭环中的作用未单独测**：本测试每周期重发同一位置（无时延），未注入位置陈旧与速度外推。
- **工具的场景配置仍需打磨**：`tools/measure_rir_from_fix/` 的简化场景不足以跑通识别确认，功能验证未完成。
- **未测多目标**：单目标，未涉及单镜筒容量约束。
